# Training code and differentiable twin

This folder holds the code that trained the learned heads and the analytic constants of submissions #337501 and #337556
(Section 5 of the write-up): the estimator source as it was trained, the generator of its differentiable Torch twin, and
the trainer.

It is research code, released as it was used. It is not a turnkey reproduction: training needs the datasets listed below,
and the run used options of `train_arm.py` that rely on helper modules not included
here (they are only imported when their flags are given).

## Provenance

`base/` is the exact source the final training runs were built from. Its identity hash, computed by the trainer
(`RuntimeTwin(device='cpu').source_sha256`), is

    ebe55efbdb15556c9a9725bd4c36171c48bb0dc750923fc351944c0f1bffb026

which matches the `source_sha256` recorded in the manifests of both training runs whose weights were averaged for the
submission. The `*.npz` files in `base/` are the starting weights of those runs (the warm start), not the submitted weights;
the submitted weights are the `*.npz` files in `../submission-337501/`.

## Layout

| Path | Contents |
|---|---|
| `base/whest_est/` | The estimator, written once against a NumPy-like array interface (`registry.py` holds every parameter). |
| `base/build.py` | Generates the single-file `flopscope` estimator and the Torch twin from the same source. |
| `base/torch_api.py`, `base/torch_twin.py` | The Torch adapter of the array interface and the twin wrapper (all layer means, differentiable). |
| `tools/train/` | The trainer: twin runtime (`runtime.py`), loss and optimiser (`engine.py`), data loading (`data.py`), checkpoints, weight export (`export.py`), folding of the heads' weights (`folding.py`). |
| `tools/*.py` | Shared helpers used by the trainer (dataset access, manifests, path checks). |
| `train_arm.py` | The run script used for the final training runs. |

## Requirements

Python 3.10, `numpy==2.2.6`, `torch` (the runs used 2.13), `flopscope==0.12.3`, `whestbench==0.16.1`, and `datasets`
for the public dataset. Run from this folder with `WHEST_BASE` set to it:

```bash
export WHEST_BASE=$PWD
python -c "from tools.train.runtime import RuntimeTwin; print(RuntimeTwin(device='cpu').source_sha256)"
```

## Data

Each update averages 16 networks; the loss is each network's final-layer MSE relative to that of the starting weights
(write-up, Eq. 20). The 15,384 training networks were:

- networks 0-799 of the public `full` split, `hf://aicrowd/arc-whestbench-public-2026` revision `v2-phase2`
  (all-layer means from 1e9 samples); point `WHEST_FULL_DATASET` at a local copy of the prepared split;
- 10,488 of the 14,048 networks of the public corpus `keenanpepper/arc-whestbench-p2-d8b-corpus-14k` (final-layer labels
  from 1e8 samples; weights regenerated from their seeds), via `WHEST_D8B`;
- 4,096 networks we generated ourselves (Torch CPU generator, seed 880000 + i, entries N(0, 2/n)) with 1e7-sample Monte
  Carlo labels and loss weight 1/8, via `WHEST_D8C`. These labels are not included; they can be regenerated by sampling.

Public networks 800-999 and the remaining corpus networks were held out for selection and testing.

## Recipe

Adam with per-group learning rates (recipe `ta-v3`, scale 1.372), 50-update warm-up then constant rates, exponential
moving averages of the weights (decays 0.995, 0.998, 0.9995, 0.9998) exported every 200 updates. The submitted weights are
the average of the 0.998 averages of two runs at update 30,600: one run warm-started from `base/*.npz`, and a copy of it
from update 20,232 on with a different data order. Appendix B of the write-up gives the details, including the export
of the weights and their transfer to the later, FLOP-reduced submitted code by a weights-only swap.
